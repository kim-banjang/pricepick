1.1. 포스트백 로그 — 쿠팡 「회원(subid)」 칸1.1. Nhật ký Postback — cột 「Thành viên (subid)」 ở Coupang

1
쿠팡 API는 https://api.adsplash.net/cou/reco_link.php?code=sleepIfUCanSTG&click_type=2&adid=&click_id= 로 호출되고 있습니다. 위 화면의 「회원」 칸에 찍힌 값은 sleepIfUCanSTG, 즉 쿠팡 API url의 code 값과 같습니다. 그러면 그 「회원」 칸은 호출할 때 쓴 url의 code 값을 그대로 가져오는 것입니까, 아니면 DB에 있는 회원의 닉네임(또는 식별 아이디)을 가져오는 것입니까?Api Coupang đang được gọi với url: https://api.adsplash.net/cou/reco_link.php?code=sleepIfUCanSTG&click_type=2&adid=&click_id= Cột thành viên trong hình trên có dữ liệu là: sleepIfUCanSTG. Đó chính giá trị code trong Coupang API url. Câu hỏi: Vậy cột thành viên đó lấy giá trị từ code trong Coupang Api url khi gọi hay là lấy giá trị từ nickname (hoặc identified_id) của user trong database?

쿠팡 API에 실려 나가는 아이디를 그대로 넣습니다. url의 code(= subid) 값입니다. DB의 닉네임이나 식별 아이디를 끌어오는 것이 아닙니다.Cột đó lấy đúng ID được gửi đi trong Coupang API. Là giá trị code (= subid) trong url. Không lấy biệt danh hay ID định danh của user trong database.
[참조][Tham khảo]칸 머리글이 「회원」이고 그 아래 작은 글씨가 subid인 것이 이 뜻입니다. 줄을 펼치면 나오는 subid 조각도 같은 값입니다.Tiêu đề cột là 「Thành viên」 và dòng chữ nhỏ bên dưới là subid — đó chính là ý này. Mảnh subid hiện ra khi mở rộng dòng cũng là cùng một giá trị.

1.2. 링크프라이스 — 단일 · 다중 상품 주문 테스트1.2. LinkPrice — test đơn một sản phẩm · nhiều sản phẩm

2
링크프라이스는 G마켓 단일 상품 주문 한 경우만 테스트했습니다. 단일 상품 주문과 다중 상품 주문 두 경우를 같이 테스트해서 포스트백 데이터가 실제로 어떻게 오는지 확인해야 한다고 봅니다. 정확히 알아야 DB 구조를 정확하게 잡을 수 있습니다.Chúng ta chỉ mới test LinkPrice cho 1 trường hợp Gmarket cho đơn hàng 1 sản phẩm. Tôi nghĩ chúng ta cần cùng test lại cho các trường hợp: đặt hàng với đơn hàng 1 sản phẩm, đặt hàng với đơn hàng nhiều sản phẩm. Để có thể xem chi tiết postback data trả về như thế nào cho 2 trường hợp trên. Biết chính xác postback data trả về cho các trường hợp để có thể cấu trúc database chính xác.
