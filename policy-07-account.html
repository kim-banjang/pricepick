계정 생애주기 신설
가입부터 연동·탈퇴·차단까지 계정이 어떤 단계를 거치고, 각 단계에서 데이터·보상이 어떻게 처리되는지(정책 기준).

1계정의 일생 (단계 흐름)

계정은 두 가지로 구분됩니다. 연동 여부 = 미연동(닉네임만) / 연동(카카오), 계정 상태 = 정상 / 정지 / 탈퇴 요청.
흐름설치 → 닉네임 가입(미연동) → (카카오 연동) → 정상 운영. 여기서 정지 또는 탈퇴로 갈라지고, 탈퇴는 즉시 처리(유예·철회 없음)되며 개인정보(PII) 파기로 종료됩니다.
출처 FunctionalSpec / DataModel(상태 정책)

2가입 · 카카오 연동

가입설치 후 닉네임만 설정하면 바로 시작(미연동). 진입 단계 소셜 로그인 없음(애플 로그인 정책상의 이유 포함).
미연동티켓·포인트 등 데이터를 기기에만 저장. 재설치하면 초기화(복구 안 됨). 쿠팡 구매의 적립 확정 대기는 D+30.
연동앱을 쓰며 카카오 연동을 유도. 연동하면 데이터가 서버에 보존되고 재설치해도 유지. 보류됐던 핵심 보상(이벤트 티켓·브론즈)이 이때 지급되며, 쿠팡 구매의 적립 확정 대기는 D+7로 단축됩니다. 링크프라이스 제휴몰은 연동과 무관하게 몰별 전환 대기일 수를 따릅니다.
전환 규칙쿠팡 구매는 카카오 연동 D+7 / 미연동 D+30에 확정된다(고정값, CMS에서 수정 불가). 링크프라이스 제휴몰 구매는 CMS 「티켓 적립 설정」에서 몰마다 정한 전환 대기일 수(기본 30일)에 확정된다. 관리자가 제휴몰 대기일 수를 줄이면 그 몰의 대기 중인 랜덤 티켓 전부에 새 값을 소급 적용한다 — 적립일로부터 새 값이 이미 지난 티켓은 저장 즉시 확정·공개되고, 못 미친 티켓은 적립일 + 새 값에 확정된다(예: 30일 → 7일로 줄이면 적립 9일째 티켓은 즉시 오픈, 3일째 티켓은 4일 뒤 오픈). 값을 늘릴 때는 이미 공개된 티켓을 다시 숨기지 않는다. (김반장 확정 2026-08-26)
계정 병합(연동 시 선택형)계정 간 자산은 합산하지 않습니다. 연동하는 카카오 계정이 신규인지 연동 이력이 있는지에 따라 아래 두 가지로 나뉩니다.
시나리오처리
01 · 신규 카카오 계정
(연동 이력 없음)		현재 닉네임 계정으로 적립된 포인트·티켓을 그대로 유지합니다.
02 · 연동 이력이 있는 카카오 계정이전 적립 내역을 표시하고 "이전 데이터 사용" 체크박스를 제공합니다(기본값 체크됨). 체크한 채로 연동하면 이전 카카오 계정 데이터를 사용하고 현재 닉네임 계정 데이터는 사라집니다. 체크를 해제하고 연동하면 현재 닉네임 계정 데이터로 대체되고 기존 카카오 계정 데이터는 리셋됩니다. 선택 전 양쪽 계정의 보유 현황을 모두 보여주고 확인을 받습니다.
어떤 경우에도 두 계정의 데이터가 합산되지 않으며, 부분 병합도 없습니다.
사용 제한: 모든 티켓(등급·이벤트)·포인트는 카카오 연동 후에만 사용 가능. 미연동(guest) 상태는 적립만 누적, 사용·교환·응모·차감 불가. 닉네임 반복가입 파밍 원천 차단.
출처 PolicySpec 14 / FunctionalSpec(시작·연동) / DataModel(보존 정책)

3닉네임 신설

중복 허용닉네임 중복을 허용합니다. 같은 닉네임을 여러 회원이 동시에 사용할 수 있습니다. 가입·변경 시 중복 검사를 하지 않습니다.
회원 식별회원 식별자는 UID입니다. 닉네임은 표시용일 뿐 식별에 쓰지 않습니다.
UID 노출닉네임 중복을 허용하므로 회원 구분을 위해 앱 화면에 UID를 표시합니다. 닉네임 아래 짧게(앞 8자) 노출하고 복사 버튼을 제공해 고객센터 문의 시 그대로 전달할 수 있게 합니다.
형식 규칙한글·영문·숫자 조합, 2~10자.
출처 김반장·이동영 부장 확정(2026-08-03) / 화면 구현(가입·닉네임 변경·마이) 기준

4로그아웃 신설

확정로그아웃 기능은 제공하지 않습니다. 앱 어디에도 로그아웃 버튼·메뉴·진입점을 두지 않습니다.
이유계정은 미연동(닉네임) 또는 카카오 연동 상태로만 존재하며, 사용자가 "로그인/로그아웃"을 오가는 구조가 아닙니다. 설치 후 닉네임만 설정하면 바로 시작되고(진입 단계 소셜 로그인 없음 — 위 2번), 그 상태가 계속 유지됩니다.
계정에서 벗어나는 유일한 경로계정 탈퇴(아래 4번)뿐입니다. 로그아웃으로 세션만 끊는 개념은 없습니다.
개발 주의데모(/app)·기획 화면 어디에도 로그아웃이 없는 것은 누락이 아니라 의도된 정책입니다. 로그아웃 UI를 새로 만들지 마십시오.
출처 김반장 확정(2026-07-14)

5탈퇴

처리설정에서 탈퇴 최종 확인을 마치면 그 자리에서 즉시 처리됩니다. 유예기간·철회 절차는 없습니다.
  • 즉시 탈퇴 — user.status = 'withdrawn'로 전환. 재로그인·계정 복구 불가.
  • 기기 로컬 데이터 삭제 — 탈퇴 처리와 함께 해당 기기의 로컬 저장 데이터(localStorage·캐시 등)를 삭제.
  • 개인정보(PII) 파기 — 닉네임·카카오 식별값 등 개인 식별 가능 항목은 탈퇴 즉시 파기합니다. 다만 부정 이용 방지에 필요한 최소한의 식별정보는 탈퇴일로부터 30일간 보관 후 파기합니다(개인정보처리방침). 회원 문서(레코드) 자체는 물리 삭제하지 않고 유지 — 티켓·결제 등 거래 기록이 회원 문서를 참조하므로 물리 삭제 시 참조 무결성이 깨짐(DB 꼬임 방지).
  • 거래·정산 기록 존치 — 티켓·결제·거래(정산) 기록은 PII가 제거된 상태 그대로 DB에 남김. 전자상거래법상 5년 보존 의무는 이 존치 기록으로 충족(별도 마스킹 배치 불필요 — 애초에 거래 기록엔 PII가 없고 user_id로만 연결).
  • 잔여 자산 소멸 — 보유 티켓·포인트는 탈퇴와 동시에 모두 소멸하며 복구되지 않습니다(이용약관 제13조).
재가입 쿨타임기본적으로 제한 없음(즉시 재가입 가능). 다만 어뷰징(제12조 해당 행위)이 확인된 계정은 회사가 재가입을 일정 기간 제한할 수 있습니다(이용약관 제13조).
본 항목은 정책 요약이며, 이용약관·개인정보처리방침 전문은 앱 내 약관 화면(정본)을 따릅니다.
출처 김반장 확정(2026-07-10, 즉시탈퇴 정책) / PricePick 이용약관 제13조·개인정보처리방침 4항 / FunctionalSpec(탈퇴 흐름) / CMS 탈퇴 관리

6운영자 차단(정지)

상태운영자가 어뷰징 등으로 계정을 정지하면, 진입 시 "운영자 계정 차단" 안내가 뜨고 정지 해제 전까지 로그인 불가.
자산정지 상태에서도 기존 잔액은 유지되지만 신규 적립·교환은 차단됩니다. 이용약관 제12조 위반 시 보유 티켓 전액 환수·영구 정지 조치 가능.
출처 FunctionalSpec(계정 차단·마이) / CMS 약관
